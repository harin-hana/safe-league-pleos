## 2. 장면별 상세

표기: 화면 = 에뮬레이터에 보이는 것. 소리 = 스피커. 차 신호 = 콘솔 HTTP 또는 adb로 넣는 값과 앱이 받는 콜백. 사람 = 시연자 행동. 자막 = 편집 자막. 나레이션 = 말.

장면 curl 묶음은 Windows PowerShell 5.1 기준이다. PowerShell의 `curl`은 다른 명령의 별칭이라 반드시 `curl.exe`로 쓴다. 묶음마다 첫 줄에서 주소를 `$v`에 담는다. 주소와 필드는 4-0절 「방법」 열 그대로이고, 값 이름이 안 맞으면 `curl.exe -s http://127.0.0.1:8088/vehicle/catalog`로 확인한다.

**핸들 부호 메모**: 콘솔 값과 앱이 받는 값은 부호가 반대다(콘솔 -30 → 앱 +30). 아래 표의 각도는 **앱이 받는 값**이고, curl에는 부호를 뒤집어 넣는다(앱 −8° = `steering=8`). 실차에서도 같은지는 미확인이라 앱 판정 모듈은 부호를 설정값 하나로 둔다.

**착석 메모**: 에뮬레이터 착석 값은 콘솔과 반대다(콘솔 Occupied → 앱 false). 앱에서 뒤집으면 실차에서 틀리므로 뒤집지 않고, 데모에서는 착석 신호를 넣지 않는다. 벨트는 벨트 경고등(Telltales SeatBelt)으로만 보여 준다.

#### 장면 0 curl 묶음 (촬영 전 초기화)

```powershell
$v='http://127.0.0.1:8088/vehicle'
curl.exe -s "$v/state"                                    # 200이 아니면 콘솔 탭 새로고침
adb shell cmd car_service day-night-mode day              # 주간
curl.exe -X PUT "$v/gear?gear=Park"
curl.exe -X PUT "$v/controls?speed=0"
curl.exe -X PUT "$v/controls?brake=0"
curl.exe -X PUT "$v/controls?steering=0"
curl.exe -X PUT "$v/turn-signal?mode=Off"
curl.exe -X PUT "$v/lights?feature=headlamp_mode&value=Off"
curl.exe -X PUT "$v/telltales/simulator?type=SeatBelt&state=On&color=Red"   # 동승석 벨트 아직
```

와이퍼 끄기 값 이름(`front_wiper=Off`)은 이번 실측에서 쓰지 않았다. 촬영 전에 catalog로 확인한다.

| 야간 | ○ `adb shell cmd car_service day-night-mode night` → `Configuration.uiMode` 야간. AAOS `NIGHT_MODE` 속성은 안 바뀜 | 실신호(uiMode). 일몰 계산 대체는 필요 없음. 0.4.1 촬영은 낮 모드라 쓰지 않음 |
| 하향등, 미등 | ○ `PUT /vehicle/lights?feature=headlamp_mode&value=LowBeam`(Position, Off) | 실신호 |
| 와이퍼 | ○ `PUT /vehicle/body?front_wiper=Low` | 실신호 |
| 벨트 | 벨트 경고등 ○(`type=SeatBelt&state=On`). 착석은 콜백은 오지만 값이 콘솔과 반대, 체결 상태 카드 없음, 동승석 벨트 경고 미지원 | **벨트 경고등만** 쓴다. 착석 값은 앱에서 뒤집지 않음(실차에서 틀림) |
| 앰비언트 | ✕ 권한(`CONTROL_CAR_LIGHTS`)을 넣어도 구역 6가지 모두 거부 | **데모 입력.** 콤보 고비와 결과 때 앱이 스스로 시도(데모 입력 줄 「앰비언트」로도 됨), 영상은 편집 띠 + 「데모 입력: 실차에서는 앰비언트 한 번」 |
| 도착(`onDestinationArrived`) | 미확인. 내비 엔진 위치가 성남에 고정이라 도착을 못 만듦 | **데모 모드에서는 주행 중 P단 = 도착.** Virtual Console에서 속도 0 → 기어 Park. 데모 입력 줄 「도착」과 adb `--es input 도착`도 남아 있고, 그 뒤 P단에 두면 결과 |
| 주의 운전(DRIVER_ATTENTION) | △ 경고등 콜백 자체는 ○(MasterWarning On → MASTER_WARNING=ON), 콘솔 목록 37종에 Driver Attention 없음 | 이 2분 대본에는 넣지 않았다. 보여 줄 때는 **데모 입력** 「주의 경고」(DRIVER_ATTENTION 1회, 자막 「데모 입력」). 주행 중에는 데모 입력 줄이 없어 「심사용 판정 보기」(1절 P11)를 켜야 누를 수 있다. 기획서와 Q&A에서 설명 |
| 카메라, 주의 구간 | △ 경로 요청 뒤 30초 동안 0건(차가 안 움직임). 제한속도는 0이 1초마다 옴 | 이 대본에는 없다. 필요하면 데모 입력 |

「데모 모드」는 설정의 스위치다. 0.4.1부터 앱 화면은 실제 쓰는 모습만 보여 주고 데모 표시를 평소에 얹지 않는다. 데모 입력 줄은 P단 화면(출발 전, 리그 중, 도착)에서 머리줄의 단계 꼬리표를 길게 누를 때만 열린다(도착, 앰비언트, 주의 경고, 카메라, 주의 구간, 다음 날, 처음부터). 누른 직후 4초 동안 그 줄 첫 칸이 「데모 입력: 다음 날」처럼 바뀐다. 주행 중에는 앱이 비켜 화면이 없다. 대신 데모 입력을 쓴 곳은 편집 자막으로 밝힌다. 숨기지 않고 보여 주는 것이 심사에서 더 낫다.

## 4. 시연 앱 세션에 넘길 작업 목록

1. 세이프 리그 전환: 출발 카드(P단), 주행 중 무화면 + 소리, 도착 결과(P단), 다음 날 카드
2. 판정 모듈: RULES 6절 의사코드. 데모 모드에서 정체 판정 창 60초 → 10초. 핸들 부호는 설정값 하나로(에뮬레이터는 콘솔과 반대)
3. 서버: Workers + D1, 리그 키와 결과 업로드, 순위 응답. 시드 6명 + 아침 기록 1건
4. 소리: 효과음 3종, TTS 1문장, 결과 효과음
5. 바탕 전환: `Configuration.uiMode`(UI_MODE_NIGHT) + 와이퍼로 세 톤. 색은 기준판 토큰. 야간 전환 때 화면이 다시 만들어지므로 상태를 잃지 않게
6. 데모 모드 스위치와 데모 입력 줄(0.4.1: P단 화면 단계 꼬리표 길게 누름, 주행 중 P단 = 도착). 버튼으로 발생시킬 것: 도착, 앰비언트, DRIVER_ATTENTION, (필요하면) 카메라와 주의 구간
7. 착석 값은 뒤집지 않는다. 벨트 연출은 벨트 경고등(Telltales SEAT_BELT)으로
8. AAOS 속성 등록(속도, 기어 보조)은 try로 감싸고 실패해도 Pleos 신호는 계속 쓴다(1차 실측 car_service 크래시, 2차 재현 안 됨)
9. 레이아웃은 앱 슬롯 1682×1210 dp 기준(폼 팩터 실측)

## 5. 열린 것

- 의견 1(저녁 결과에 「오늘 아침 2위」 한 줄)은 규칙 세션이 11/05 채택(`RULES_REPLY_2026-11-05.md`). 실제 저녁 결과에만 붙고, 아침 리그 하나인 0.4.1 데모에서는 나오지 않는다
- 순위표 별명 6개는 익명 별명 규칙(RULES 7절)대로. 예: 아침첫차, 아침7시42, 올림픽대로, 깜빡이장인, 비오는날, 월요일만
- 「어제 아침보다 0.4 올랐어요」는 어제 아침 기록이 있어야 한다. 서버 시드에는 어제 아침 행이 없어 앱 시드 `Ghost.yesterdayMe` 99.3으로 채운다
- 【확인】 외기온 신호, 제한속도 0일 때 내비 상단 표시, 와이퍼 끄기 값 이름, 전체 화면 모드가 따로 있는지(홈 화면 슬롯 규칙)

화면 구성 결정(10/31, 11/06 폼 팩터 실측 반영): 어느 문서에도 다른 앱 위에 겹쳐 그리는 방법이 없다. 앱은 오른쪽 앱 슬롯(1682×1210 dp, 비율 약 1.39:1)에 뜨고 왼쪽 853 dp는 호스트가 내비 또는 위젯을 둔다. 앱 슬롯 안 왼쪽 칸은 내비가 이미 보여 주는 경로 요약이 아니라 우리 앱만 아는 것으로 채운다. 출발 때는 「리그 자격 확인」(목적지 있음, 예상 35분, 15km, 아침 시간대, 같은 길 7명이 체크로 섬), 도착 때는 「경로 띠」(출발에서 도착까지 가로 선 하나에 감점 자리 점 3개와 콤보 고비를 올린 1차원 지도). 세로 1210 dp 여유는 이 두 칸에 쓴다. 주행 중에는 앱이 뒤로 가고 내비가 앞에 있으므로 「주행 중 화면 없음」은 그대로 성립한다.

v1의 열린 위험(P단 신호로 앱이 스스로 앞으로 나오는가)은 닫혔다. 에뮬레이터에서 포그라운드 서비스가 GEAR_PARK를 받고 startActivity로 앱 화면을 올렸고(①), 알림도 함께 게시됐다. 실차에서도 같은지는 실차 확인 때 본다.
